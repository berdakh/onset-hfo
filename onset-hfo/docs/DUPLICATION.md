# Two repositories, and what to do about it

There are two repositories, two deployed Streamlit apps and two GitHub Pages
sites under one project name. Before the expo that has to read as one project
rather than as a thing that was built twice. This document measures what is
actually duplicated, says plainly what must **not** be merged, and gives the
ordered plan.

Companion documents: [`POSTER.md`](POSTER.md), [`EXPO.md`](EXPO.md).

---

## What exists

| | `berdakh/onset` | `berdakh/onset-hfo` |
|---|---|---|
| What it is | teaching prototype on a **synthetic** five-patient cohort | the instrument, on **public recordings of real patients** |
| Python | 762 lines (`onset/` + `app/`) | 14,870 lines (`onset_hfo/`, `onset_agent/`, `app/`) |
| App | <https://berdakh-onset.streamlit.app/> — Home + 7 pages | <https://onsetnu.streamlit.app/> — Home + 9 pages |
| Site | <https://berdakh.github.io/onset> — index, tutorial, clinical guide, mockup (190 KB of HTML) | <https://berdakh.github.io/onset-hfo/> — results page + handout |
| Data | generated by `onset/synth.py` at startup | ds003498 and ds003029, both CC0 |

The size difference is the single most important fact here: the teaching
prototype is 5% of the code. Any plan that treats the two as peers to be
unified will cost more than it saves.

---

## What is genuinely duplicated

Measured, not guessed.

1. **The app shell.** Both apps have an `app/common.py` whose job is a
   `banner()` plus a sidebar link row, and six of the page names are identical:
   `Home`, `Report`, `Assistant`, `Data`, `Architecture`, `Research`. Two more
   are the same page renamed — `Patient`→`Recording`, `Models`→`Detectors`.
   `onset-hfo/app/common.py` says so in its own docstring: *"Mirrors
   berdakh/onset's app/common.py on purpose."*

2. **The theme.** `.streamlit/config.toml` is byte-identical in both
   repositories apart from a comment. Nothing keeps it that way.

3. **The standing disclaimer.** The same principle — research prototype, every
   number cites its evidence, no recommendation exists in the product — is
   written out twice, in two wordings, in two `banner()` functions.

4. **The project framing.** The lab, the mission and the "decision support, not
   diagnosis" sentence appear in two READMEs, two site headers and two app
   banners. Five of those six were written independently.

5. **The front door.** Until this week both sites opened as if each were the
   project's home page, and neither linked the other.

6. **The link vocabulary.** The two sidebars name the same destinations
   differently — one calls the illustrated guide "Tutorial", the other
   "Implementation walkthrough". A reader moving between the apps cannot tell
   whether those are the same document.

---

## What is not duplicated, and must not be merged

Equally measured. These look like duplication and are not.

1. **The Python.** Zero shared modules. `onset/synth.py` generates a synthetic
   cohort; `onset_hfo/datasets.py` fetches byte ranges out of a real BIDS
   archive. `onset/models.py` (85 lines, two baseline rankers) and
   `onset_hfo/models.py` (923 lines) share a filename and nothing else.
   Extracting a common package would couple a teaching artefact to the pipeline
   every measured number depends on, in exchange for no reuse that exists
   today. **Do not.**

2. **The two long-form guides.** `onset/docs/tutorial.html` (73 KB) teaches
   *how the system is built* — iEEG, features, models, evaluation without
   leakage, an optional agent lab. `onset-hfo/site/TUTORIAL.html` (58 KB)
   teaches *whether the results are true* — what the archive does and does not
   contain, why a filtered sharp edge looks like a ripple, five attacks and the
   one that landed. Same subject, opposite questions. Merging them would
   produce one document that does neither job. **Cross-link them instead.**

3. **`onset/docs/clinical-guide.html`.** 62 KB on what presurgical evaluation
   actually involves. Nothing in `onset-hfo` overlaps it, and for the expo
   audience it is the most valuable page either repository has.

4. **The `Outcome` page.** Only `onset-hfo` has one, because only `onset-hfo`
   has outcomes. It has no counterpart to converge with.

## The decision

**One project, two instruments.** Fixed vocabulary, used everywhere from now
on:

- **Onset** — the project. Never an app.
- **Onset Teaching Prototype** — `berdakh/onset`, synthetic data, built to be
  read end to end.
- **Onset-HFO** — `berdakh/onset-hfo`, public patient recordings, built to be
  checked.

"The Onset app", unqualified, is banned: it is the phrase that made two things
look like one broken thing.

**One front door:** <https://berdakh.github.io/onset>. It introduces the
project, leads with Onset-HFO because that is what a clinician came for, and
keeps the teaching prototype clearly labelled as such. The Onset-HFO site is a
**results page**, not a second home page.

## The plan

Ordered by benefit per unit of work. Items 1–3 are done.

| # | Action | State |
|---|---|---|
| 1 | Make the Onset site the front door: nav and hero lead to Onset-HFO, §04 carries the real-data result, the footer links both sites | **done** — berdakh/onset#1 |
| 2 | Give the Onset-HFO site and app links back to the Onset site, so neither is a dead end | **done** |
| 3 | Align the two sidebars' link vocabulary so the same document has the same name in both apps | **done** — see below |
| 4 | Retire the teaching prototype's thin pages. Its `Data`, `Architecture` and `Research` pages restate what the site says at greater length and better. Replace each with a short page that links the site section | **done** — berdakh/onset#3, with its premise revised; see below |
| 5 | Write the standing disclaimer once. Both banners keep an identical structure and differ only in the sentence naming the data; the canonical text lives in this repository and the other copies it | **done** — canonical copy here, adopted in berdakh/onset#3 |
| 6 | Mark the theme file. A header comment in each `.streamlit/config.toml` naming the other repository as its twin, so whoever edits one knows a second copy exists | **done** — both `.streamlit/config.toml` files carry the header |
| 7 | Cross-link the two long-form guides: one sentence at the top of each saying which question the other answers | **done** — both guides open with it; the target is published now |
| 8 | Add the four-line "stays in step" checklist below to both repositories' contributing notes | **done** — `CONTRIBUTING.md` here, the README there |

**Item 4's premise did not survive checking, and the item was revised rather
than executed.** It said to retire the teaching prototype's `Data`,
`Architecture` and `Research` pages as restatements of the site. Measured
against the site, that held for one of the three:

| page | verdict |
|---|---|
| `Data` | **Not a restatement.** It is an interactive signal browser, and the site's own §02 *links to it* — "Open the synthetic signal viewer". Retiring it would have broken the front door's own link and deleted the one thing the site cannot do. |
| `Architecture` | **Partly.** The site covers the five implemented steps; the page's full-system-against-prototype table is on the site nowhere. |
| `Research` | **Yes.** Lab, PI, repositories and what-is-implemented are all in the site's §05. That half is cut; the MSc theses and the five inherited principles stay, being published nowhere else. |

So each page links the site section it draws on and only the restated
paragraph was removed. The lesson is the one this project keeps relearning:
**a plan item written from an impression needs re-measuring before it is
executed**, and "these pages are thin" was an impression.

### Item 5: the canonical disclaimer

Lives in `onset-hfo/app/panels.py` — the module that imports no Streamlit,
so a test can read it where Streamlit is not installed. Structure is fixed;
exactly one line differs between the two apps.

```python
DISCLAIMER_LEAD = "Research prototype — not a medical device."
DISCLAIMER_TAIL = ("Every number cites the window it came from. There is no "
                   "recommendation anywhere in this product; the clinician "
                   "decides.")
```

The line that differs, because only one of the two runs on real recordings:

| repository | `DATA_SENTENCE` |
|---|---|
| `onset-hfo` | Real public recordings, real expert markings, real surgical outcomes — and nothing here is validated for clinical use. |
| `onset` | A **synthetic** five-patient cohort, generated at startup — there is no patient data here, and nothing here is validated for clinical use. |

The teaching prototype's wording is the one place the disclaimer must *not*
match, and it is the more important of the two to get right: a reader who
mistakes the synthetic cohort for patients has been misled about the only
thing that matters.

### Item 7, and the dead link it nearly shipped

Both guides now open by naming the question the other answers:
`site/TUTORIAL.html` points at the implementation walkthrough, and
`onset/docs/tutorial.html` points back.

**Writing the second half exposed that the first half's target did not
exist.** This repository publishes `site/` to GitHub Pages and nothing else,
so `berdakh.github.io/onset-hfo/TUTORIAL.html` was a 404 and had been for as
long as the file existed — the project's longest document, the one that argues
whether its own results are true, was reachable only by cloning the
repository. The file moved from `docs/` to `site/`, which is where CI looks,
and the two READMEs that pointed at the old path now point at the published
URL.

Worth stating as a rule rather than an anecdote: **the two repositories
publish different directories.** `onset` publishes `docs/`; `onset-hfo`
publishes `site/`, with `docs/` holding markdown read on GitHub. A path that
works in one is not a path in the other.

### What "done" means for item 3

`onset-hfo/app/common.py`'s sidebar called the Onset project's illustrated
guide "Tutorial" while the Onset site, after #1, calls it the implementation
walkthrough — so the same document had two names and a reader could not tell.

Both sidebars now open with the same four destinations, under the same names,
in the same order:

> Clinical guide · Implementation walkthrough · Results & docs · Onset project

followed by two entries that differ by design — the other instrument's app, and
this repository's code. Each row carries a comment pointing at this document,
so whoever edits one knows the other exists.

### The "stays in step" checklist

Four things, and only these four, must match across the repositories. Anything
not on this list is allowed to differ.

1. The **standing disclaimer**'s structure and its no-recommendation sentence
   — `onset-hfo/app/common.py`'s `DISCLAIMER_LEAD`, `DATA_SENTENCE` and
   `DISCLAIMER_TAIL`. Only `DATA_SENTENCE` may differ.
2. The **shared page names**: `Home`, `Report`, `Assistant`, `Data`,
   `Architecture`, `Research`.
3. The **sidebar link row** — same destinations, same names, same order.
4. `.streamlit/config.toml`, which carries a `TWIN FILE` header saying so.

There is no mechanism that can enforce this across two repositories, and
pretending otherwise with a submodule or a published package would cost more
than the four items are worth. The honest control is that the list is short,
written down in both places, and each item carries a comment naming its twin.

The one part that *is* enforced is the part that lives in one repository:
`tests/test_app.py` checks that the banner is built from the three constants
rather than from a fourth copy of the sentence, and that the wording this
document quotes is the wording the code ships. A checklist that has already
been contradicted by the code is worse than no checklist.

## What we are deliberately not doing

- **No monorepo.** The teaching prototype deploys from its own root and is
  meant to stay clonable and readable on its own. Merging the repositories
  would make the 762-line artefact inherit a 14,870-line dependency surface.
- **No shared Python package.** See above — there is no shared code to extract,
  only a shared *vocabulary*, and vocabulary is cheaper to keep in step in prose
  than in a release cycle.
- **No retiring the teaching prototype.** It is the only place a student can
  read a complete pipeline in an afternoon, and the only one whose data can be
  regenerated with no download. It loses its claim to the front page, not its
  reason to exist.
- **No second Pages site being folded into the first.** The results page is
  regenerated from `site/` by CI on every push to `master`; hosting it under
  the other repository would break that and gain nothing.
